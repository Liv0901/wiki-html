# 工具使用

> 摘要：工具讓 Agent 從「只會說」變成「能做事」：查資料、算數、執行程式、操作系統。

## 重點
- 工具讓 LLM 取得權重裡沒有的資訊與能力，例如即時資訊、程式執行與專有資料。[S3]
- Toolformer 證明 LM 可以用自我監督的方式學會「何時呼叫哪個 API、帶什麼參數」，工具包含計算機、問答系統、搜尋引擎、翻譯與行事曆。[S6]
- 工具的定義與說明文件要像寫給新進同事一樣清楚；Anthropic 稱之為「Agent–電腦介面（ACI）」，值得投入和人機介面一樣多的心力。[S1]
- Model Context Protocol（MCP）是 2024 年 11 月發布的開放標準，讓 AI 應用以統一方式連接各種資料來源與工具。[S12]
- SWE-agent 設計專用的 Agent–電腦介面，讓 Agent 能建立與編輯程式檔、瀏覽整個程式庫並執行測試，在 SWE-bench 與 HumanEvalFix 分別達到 12.5% 與 87.7% 的 pass@1。[S18]

## 說明
### Function calling 的流程
1. 開發者把工具的「名稱、用途、參數格式」提供給模型。
2. 模型判斷需要時，輸出一段結構化的工具呼叫（例如 JSON）。
3. 程式真正執行工具，把結果當作 **Observation** 回傳給模型（見 [[agent-loop]]）。
4. 模型根據結果決定下一步。

### 好工具的設計原則（整理自 [S1]）
- 名稱與參數直覺，附範例與邊界情況說明。
- 盡量「防呆」，讓模型不容易用錯（例如要求絕對路徑）。
- 實際測試模型怎麼用工具，再迭代修改。

### 工具＝風險
能動手就可能闖禍，工具權限要最小化，詳見 [[risks]]。
