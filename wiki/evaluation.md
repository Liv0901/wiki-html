# 評估

> 摘要：Agent 走的是多步路徑，評估不能只看最後一句話，還要看「有沒有真的把事情做完」與過程是否合理。

## 重點
- SWE-bench 從 12 個熱門 Python 專案的真實 GitHub issue 與 PR 中整理出 2,294 個題目，要求模型修改程式碼來解決問題。[S11]
- SWE-bench 發表時，表現最好的 Claude 2 只解出 1.96% 的題目，顯示真實軟體任務對 Agent 仍然困難。[S11]
- 部署前應在沙盒環境中大量測試，並設置適當的防護機制。[S1]
- 能以客觀方式驗證結果的任務（例如程式可以跑測試）特別適合 Agent，因為回饋可以直接用來迭代。[S1]
- AgentBench 用 8 個不同環境評估「LLM 當 Agent」的能力，發現頂尖商用模型表現強，但與多數 70B 以下的開源模型差距明顯。[S16]
- AgentBench 指出 Agent 失敗的主因是長程推理、決策與遵循指令的能力不足。[S16]

## 說明
### 評估什麼？
| 面向 | 問題 | 例子 |
|---|---|---|
| 任務成功率 | 有沒有完成？ | 測試是否通過（SWE-bench） |
| 過程品質 | 步驟合理嗎？有沒有亂用工具？ | 檢查行動軌跡 |
| 成本與效率 | 花了多少步、多少 token、多久？ | 迭代次數上限 |
| 安全性 | 有沒有做出不該做的事？ | 越權呼叫、洩漏資料（見 [[risks]]） |

### 常用方法
自動化測試、人工審核、以 LLM 當評審（LLM-as-a-judge），以及在固定基準上比較。
