# Workflow 與 Agent 的設計模式

> 摘要：不是所有 LLM 應用都需要 Agent。先用最簡單的方案，只有在真的需要時才增加複雜度。

## 重點
- 先找最簡單的解法，只在必要時增加複雜度；很多情況下，單次 LLM 呼叫加上檢索與範例就夠了。[S1]
- 提示鏈（Prompt chaining）：把任務拆成固定的連續步驟，每一步處理上一步的輸出，中間可加檢查關卡。[S1]
- 路由（Routing）：先分類輸入，再交給專門的後續流程處理。[S1]
- 平行化（Parallelization）：把任務切段同時處理（分段），或同一任務跑多次再投票（投票）。[S1]
- 協調者－工作者（Orchestrator-workers）：中央 LLM 動態拆解任務、分派給工作者 LLM，再整合結果。[S1]
- 評估者－最佳化者（Evaluator-optimizer）：一個 LLM 產生答案，另一個 LLM 評估並給回饋，反覆迭代。[S1]

## 說明
### 決策指南
```
任務步驟能事先寫死嗎？
 ├─ 能 → 用 Workflow（提示鏈／路由／平行化）
 └─ 不能，需要依結果決定下一步
       ├─ 有明確評估標準 → 評估者－最佳化者
       ├─ 子任務無法預先知道 → 協調者－工作者
       └─ 開放式、多步、需工具 → Agent（Agent 迴圈）
```
（決策樹為本 Wiki 依 [S1] 內容整理）

### Graph 與 Loop
- **Workflow 本質上是一張「圖（graph）」**：節點與邊由開發者事先定義。
- **Agent 本質上是一個「迴圈（loop）」**：每一輪由模型決定下一個動作。
- 實務系統常是混合：外層是圖，某些節點內部是 Agent 迴圈。
